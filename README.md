# Halloween HR Game

Демо на Phaser + TypeScript, Express + Socket.IO. Одна сессия — одна комната, 2–10 игроков. Выбор из 19 персонажей при входе.

## Ручной запуск без Docker и nginx

Нужен Node.js 22.12+ (проверено на Node.js 24). В корне проекта один раз установите зависимости:

```sh
npm ci
```

Затем одна команда собирает клиент и сервер и запускает игру:

```sh
npm start
```

Откройте http://localhost:3001/admin, войдите с паролем из консоли и создайте комнату. Отправьте участникам полученную ссылку с параметрами room и invite, заменив localhost на IP или домен сервера. Корневой адрес без приглашения показывает сообщение о необходимости ссылки от организатора. Комнаты создаются только в админке. Игра, HTTP API и Socket.IO работают на одном порту 3001.

Порт меняется переменной `PORT`, адрес прослушивания — `HOST` (по умолчанию `0.0.0.0`). Остановка — Ctrl+C в терминале запуска. Сессии в оперативной памяти при остановке сбрасываются. Express сам отдаёт собранные файлы из dist; дополнительный веб-сервер не требуется.

## Разработка

`npm run dev` одновременно запускает сервер на 3001 и Vite на 5173. Vite проксирует Socket.IO и API на сервер. Если порт 3001 занят запущенным `npm start`, сначала остановите его. Отдельные команды: `npm run dev:server`, `npm run dev:client`.

`npm test` проверяет очередь, повторные и чужие броски, 10 одновременных клиентов, независимость комнат, восстановление игрока, достижение финиша и каталог персонажей. `npm run build` проверяет TypeScript и собирает обе части.

## Правила демо

- При входе игрок выбирает персонажа и ник. Одинаковые персонажи разрешены; у каждого игрока своя цветная подставка.
- Все начинают на клетке 1. Подключение игроков не запускает партию: администратор нажимает «Начать игру» в /admin, когда онлайн хотя бы два участника. До запуска кубик заблокирован, очередь не назначена. После запуска бросок разрешён только текущему игроку при наличии хотя бы двух подключённых участников.
- Сервер выбирает равновероятное число 1–6 через node:crypto.randomInt. Клиент передаёт только запрос на ход, а не результат или позицию.
- Пока кубик вращается и персонаж идёт по клеткам, новые броски заблокированы на сервере и у всех клиентов.
- После движения очередь переходит к следующему подключённому игроку. Первый достигший клетки 100 побеждает; для новой партии откройте новую комнату.
- Отключившийся игрок пропускается. Уже начатый бросок завершается. Его место и позиция сохраняются 2 минуты; перезагрузка вкладки восстанавливает игрока по токену из sessionStorage. По истечении срока место освобождается.
- Все данные хранятся только в памяти одного процесса. Перезапуск сервера сбрасывает партии. Нет БД, регистрации, межсерверного хранения и горизонтального масштабирования.
- Сервер синхронизирует игроков, броски, очередь, карточки событий, подбор предметов, порталы и финиш.

## Структура

`server/GameRoom.ts` — правила и состояние комнаты; `server/app.ts` — Express и сетевые события; `shared/game.ts` — общий протокол и параметры игры; `shared/characters.ts` — общий каталог персонажей; `src/game/GameSession.ts` — соединение клиента; `src/game/PlayerPieces.ts` — отображение движения; `src/ui/JoinPanel.ts` — выбор персонажа.

API: GET /api/health. События Socket.IO: game:join, game:roll, game:state.

## Подготовка графики

При npm start / npm run build и npm run dev:client облегчённые текстуры автоматически создаются через sharp. Исходные PNG остаются неизменными. Генерируемые WebP находятся в public/game-assets, размеры кадров автоматически пересчитываются. Для добавленных или изменённых PNG перезапустите команду разработки, чтобы обновить подготовленные текстуры.

Плитки, свечение и сложные подложки рисуются в текстуры один раз. Звёзды используют общую текстуру и один таймер. Объекты вне камеры скрываются; персонажи обрабатываются отдельно. Начальный экран не создаёт Phaser; после первого входа скрытая сцена приостановлена. Частота кадров: до 60 во время партии, 30 при ожидании, паузе и финише. Настройки — src/config/render.ts. Отчёт о размере ресурсов — .asset-cache/metrics.json (расчёт RGBA не равен полной памяти браузера).

### Админка

Страница `/admin` работает на том же сервере, отдельный запуск не нужен. Показывает все комнаты, число участников и игроков онлайн, персонажей, позиции и текущий ход. Обновляет данные каждые 2 секунды.

При каждом запуске сервер печатает временный пароль администратора в консоли. Чтобы использовать постоянный пароль, задайте переменную окружения `ADMIN_PASSWORD` перед `npm start` (PowerShell: `$env:ADMIN_PASSWORD = 'ваш-пароль'`; Linux: `ADMIN_PASSWORD='ваш-пароль' npm start`). Пароль не включается в клиентскую сборку. Авторизация действует 8 часов, хранится в памяти сервера; перезапуск завершает вход в админку. При публикации в интернете используйте HTTPS для защиты пароля при передаче.

- **Сбросить сессию**: сохраняет игроков и их персонажей, возвращает всех на клетку 1, отменяет бросок и победителя. Комната снова ожидает ручного запуска через «Начать игру».
- **Выгнать**: удаляет участника, отключает его соединение и аннулирует старую сессию. Это исключение из текущей игры, а не постоянный бан; новый вход возможен через кнопку «Вернуться ко входу» на экране исключения, без обновления страницы.
- **Переместить**: принимает номер клетки от 1 до текущего размера поля, отменяет текущий бросок и сразу синхронизирует позицию. Перемещение на финиш объявляет победителя; перемещение победителя назад продолжает игру.

В разработке `/admin` также доступна на Vite-порту; API идёт через существующий proxy. Для применения изменений серверного кода при ручном запуске остановите сервер через Ctrl+C, затем выполните `npm start`. Текущие игровые комнаты при перезапуске очищаются, поскольку хранятся в оперативной памяти.

### Один игрок в браузере

Перед подключением клиент получает подписанную HttpOnly cookie через POST /api/player. Она общая для вкладок; IP и никнейм для идентификации не используются. Сервер разрешает только одно место на этот браузер во всех комнатах: вторая активная вкладка и вход в другую комнату блокируются. После разрыва связи вход в ту же комнату восстанавливает прежнего персонажа, даже без токена из sessionStorage. Место сохраняется на существующий срок переподключения (2 минуты), затем удаляется при очистке. «Выйти из игры» и исключение администратором освобождают место сразу.

Cookie не заменяет учётную запись: другой браузер, отдельный профиль, инкогнито или очистка cookie дают новую личность. Для ограничения на уровне человека потребуется авторизация. Все вкладки должны использовать один адрес сервера (не смешивать localhost и 127.0.0.1). Состояние комнат и ключ подписи остаются в оперативной памяти; после перезапуска выдаётся новая cookie.
### Локальная игра из нескольких вкладок

Команда npm run start:dev собирает клиент и сервер и запускает игру в режиме разработки. Откройте http://localhost:3001/?room=demo в нескольких вкладках: каждая может войти отдельным персонажем. Для разных комнат меняйте параметр room. Переподключение с сохранённым токеном возвращает прежнего персонажа; если дублированная вкладка скопировала активную сессию, первый вход отклоняется, а повторное нажатие «Начать игру» создаёт отдельного игрока.

Дев-сервер слушает только 127.0.0.1; исключение из проверки одной личности разрешается только для локальных соединений с адресом и Origin localhost/127.0.0.1/::1. Флаг включается на сервере через --dev, параметр URL не может включить его. Обычный npm start сохраняет ограничение одного игрока во всех вкладках. Остановка — Ctrl+C в терминале запуска.

Команда npm run dev также включает дев-режим и запускает сервер с отслеживанием изменений и клиент Vite на http://localhost:5173.
### Комнаты по приглашениям

В /admin укажите название комнаты (латинские буквы, цифры, дефисы и подчёркивания, до 32 символов) или оставьте поле пустым для автоматического названия. Нажмите «Создать комнату». В карточке комнаты появится готовая ссылка и кнопка «Скопировать ссылку». Ссылка содержит параметры room и invite; вход в такую комнату без верного invite запрещён и в обычном, и в дев-режиме.

Пустые комнаты, созданные администратором, сохраняются в памяти. Сброс игры сохраняет ссылку. Перезапуск сервера удаляет комнаты и делает старые приглашения недействительными; их нужно создать заново. Свободный вход по room (например demo) разрешён только в локальном дев-режиме. Токен приглашения доступен в админке, но не включается в общие игровые снимки.
### Проверка приглашения при входе

В обычном режиме корневой URL и ссылки без invite показывают экран «Нужна ссылка приглашения». Неверные и устаревшие приглашения отклоняются. GET /api/entry проверяет ссылку перед подключением клиента, game:join повторно проверяет её на сервере. Прямое обращение к Socket.IO не позволяет создать комнату или войти без приглашения. В локальном дев-режиме корень и ?room=demo продолжают работать без токена; для комнаты с приглашением токен требуется и в этом режиме.
### События оранжевых клеток

Расположение 25 клеток одинаково для сервера и клиента: shared/board-events.ts и shared/event-layout.ts. Текст карточки не связан с номером клетки: сервер перемешивает все 10 карточек, выдаёт их без повторов внутри набора и перемешивает снова.

server/events/catalog.ts — единая структура текстов, вариантов ответов и действий. Вариант содержит outcome; исход может содержать actions, условный бросок roll с ветками values, или confirm с возможностью отказа. server/events/execute.ts выполняет общие команды: move (фиксированное число либо число с кубика), leader, nearest-behind, modifier, double-roll, skip; Цели: self, others, ahead (строго впереди) и chosen (выбранный игрок). Дополнительные карточки добавляются через каталог, без отдельной логики в сцене.

server/events/BoardEvents.ts управляет стадиями choice, confirm, roll, rolling, result. Карточку видят все, действует только её владелец. Последствия вариантов не передаются клиентам до выбора; каталог действий отсутствует в клиентской сборке. До завершения карточки обычные броски заблокированы. На выбор или дополнительный бросок даётся 60 секунд. Готовое последствие ожидает кнопки «Продолжить»; до подтверждения ни позиции, ни бонусы не меняются. Если владелец отключится и не вернётся за время ожидания, неподтверждённое событие отменяется. При переподключении возвращается та же карточка; сброс или административное перемещение отменяют её.

Минус 1 и плюс 5 применяются один раз к сумме следующего обычного броска; минимальное движение — 0. Два броска выполняются последовательно и суммируются в одном ходу. Дополнительные броски событий не тратят эти бонусы. Перемещения ограничены стартом и финишем. Если последствие переместило игрока на новый эффект, после движения открывается следующая карточка. Игроки на одной клетке считаются наравне; для конфликта интересов берётся ближайшая строго меньшая позиция, а если позади никого нет, игрок остаётся на месте.
### Подтверждение и анимация событий

Исполнитель сначала строит план последствий на копиях состояния. Только кнопка «Продолжить» применяет план. Перемещения публикуются как общая серверная фаза moving со списком маршрутов и временем начала/окончания; обычные броски заблокированы до завершения всех маршрутов. PlayerPieces и ProgressTrack используют один расчёт позиции из shared/movement.ts, поэтому вперёд, назад и групповые перемещения одинаковы у всех клиентов. Максимальная длительность длинного перемещения задаётся gameConfig.maxEventMoveDuration.

Попадание на оранжевую клетку сопровождается короткой вспышкой, двумя ромбовидными волнами и искрами. После небольшой паузы появляется карточка. Параметры — src/config/event-presentation.ts; эффект создаёт только временные объекты и поддерживает уменьшение анимации.
### Объекты на клетках

Позиции объектов рассчитываются общей функцией shared/board-pickups.ts, без импорта изображений на сервер. На поле из 100 клеток размещены 6 монет, 6 призраков, 6 тыкв, 12 сладостей, 2 метлы и 3 зелья. Расстановка рассчитана на 6 игроков: маршрут разделён на 6 участков, каждый содержит монету, призрака, тыкву и две сладости. Пять массовых эффектов распределены по разным участкам после стартового; метлы находятся в середине маршрута. Первые и последние 6 клеток свободны от предметов. Позиции подбираются совместно с равномерными промежутками, а не отдельной случайной раскладкой для каждого типа. Параметры находятся в pickupBalance. Их клетки не пересекаются с оранжевыми событиями. Вариант candy-ghost использует ту же бежевую модель и вызывает событие призрака.

- Призрак: +5 клеток.
- Монета: пропуск следующего хода.
- Тыква: выбор другого участника (себя выбрать нельзя); выбранный игрок пропускает ход.
- Сладость: один дополнительный бросок с движением вперёд на его результат.
- Метла: два дополнительных броска, движение на их сумму; все остальные участники пропускают ход.
- Зелье: игроки, стоящие строго впереди, отступают на 5 клеток; стоящие наравне и позади остаются на месте.

Все тексты и действия находятся в eventCatalog. Объектные карточки фиксированы по типу объекта и не входят в случайную колоду оранжевых клеток. Эффект срабатывает при остановке на клетке после обычного броска или перемещения из другой карточки. Прохождение мимо не активирует эффект. При подборе объект приподнимается, уменьшается и исчезает у всех игроков. Подобранный предмет скрывается у всех, пока подобравший игрок остаётся на его клетке, в том числе после переподключения. После завершения ухода обычным броском, эффектом или административным перемещением предмет возвращается и доступен для нового подбора. Выход или исключение игрока тоже возвращает предмет. Само появление не запускает эффект для стоящих на клетке игроков; требуется новое попадание. Защита цепочек от повторного срабатывания на той же клетке в течение одного хода сохраняется. Метлы плавно парят и покачиваются, зелья парят и слегка мерцают; параметры анимации находятся в src/config/pickups.ts. Все парящие предметы обновляются в одном общем цикле без отдельных таймеров. «Продолжить» подтверждает последствия и запускает общую анимацию движения.
При наступлении своего хода игрок видит «ТВОЙ ХОД» по центру экрана в течение 2,4 секунды с лёгким затемнением фона. Уведомление не перехватывает нажатия. Длительность находится в src/config/turn-notice.ts.

### Уведомления и пауза

До ручного запуска все участники видят по центру «ОЖИДАЕМ НАЧАЛА ИГРЫ». После запуска появляется «ИГРА НАЧАЛАСЬ», затем текущий игрок видит «ТВОЙ ХОД». Статус ожидания убран от кубика.

В админке кнопка «Пауза» приостанавливает запущенную партию; повторная кнопка «Продолжить игру» возобновляет её. Все участники видят постоянное сообщение «ИГРА НА ПАУЗЕ», после продолжения — краткое «ИГРА ПРОДОЛЖАЕТСЯ». Пауза доступна только авторизованному администратору. Сервер отклоняет броски и действия карточек, останавливает игровые часы и таймеры обычных бросков, событий и перемещений. После продолжения сохраняется оставшееся время; игроки и маркеры прогресса не перескакивают вперёд. Сброс во время паузы отменяет таймеры, снимает паузу и возвращает комнату в ожидание нового запуска. Тексты и длительность уведомлений — src/config/turn-notice.ts.
В колоду оранжевых событий добавлены «Лучшая версия себя» (+6 клеток) и «Зомби Код AI» (два дополнительных броска, движение вперёд на их сумму). Движение выполняется после подтверждения «Продолжить», ограничено финишем и может запустить следующую карточку на клетке назначения.

### Порталы и цепочки эффектов

Три портала размещаются общей функцией shared/board-portals.ts, без пересечений с предметами и оранжевыми клетками. Карточка портала предлагает бросок: 1, 3, 6 — на 10 клеток вперёд; 2, 4, 5 — на клетку лидера, то есть игрока дальше всех по маршруту. Если сам игрок уже лидирует, он остаётся на месте. Перемещение подтверждается кнопкой «Продолжить» и использует общую анимацию. Портал остаётся на поле и доступен в следующих ходах; его изображение показано в карточке.

После любого подтверждённого перемещения проверяются клетки назначения всех передвинутых игроков. Новые оранжевые события, предметы и порталы открываются по очереди; решение принимает игрок, попавший на соответствующую клетку. После массового перемещения первым обрабатывается автор эффекта, затем остальные в порядке мест в комнате. Основная очередь ходов остаётся заблокированной до завершения всей цепочки. Прохождение мимо клетки ничего не активирует. Для защиты от циклов одна клетка срабатывает не более одного раза на каждого игрока в течение исходного хода. Достижение финиша завершает игру до открытия новой карточки. Пауза сохраняет текущую карточку и очередь цепочки, сброс и административное перемещение отменяют её.
### Финиш

Первый игрок, достигший клетки 100, становится единственным победителем. Сервер завершает партию, очищает очередь цепочек и таймеры, снимает текущий ход и отклоняет новые броски и действия карточек. Если массовое движение ведёт нескольких участников к финишу, игра останавливается при самом раннем прибытии; при одинаковом времени используется стабильный порядок перемещения (автор эффекта, затем места игроков). Остальные участники не занимают клетку 100.

Победитель видит отдельную финальную карточку с поздравлением «Поздравляем, коллега! Да-да, КОЛЛЕГА!» и полным текстом приглашения в компанию. Остальные видят имя и аватар победителя. Обе карточки позволяют выйти из игры. Тексты — src/config/finish.ts; интерфейс — src/ui/FinishPanel.ts и FinishPanel.css. Сведения о победителе сохраняются отдельно в состоянии комнаты, поэтому переподключение или выход победителя не меняют результат. Сброс из админки убирает финальные карточки и возвращает всех на старт в ожидание нового запуска.
### Оптимизация загрузки и итоговая проверка

Стартовый экран и проверка приглашения находятся в src/index.ts и src/entry. Phaser, игровая сцена и текстуры окружения загружаются динамически из src/game/start-game.ts после нажатия «Присоединиться» либо при восстановлении сохранённой сессии. При неправильном приглашении движок не создаётся. Ошибки загрузки показываются на экране входа. Модуль Phaser выделен в отдельный кэшируемый чанк.

Начальный JavaScript производственной сборки уменьшен с 1 515 606 до 14 610 байт (примерно на 99%). С Brotli передаётся около 5 240 байт. Это размер начального JS, без изображений, CSS и шрифтов; полный движок не удалён и загружается после входа. Из файлов шрифтов оставлены только WOFF2 с кириллицей и латиницей.

npm run build автоматически создаёт .br и .gz через scripts/compress-build.mjs и печатает отчёт scripts/bundle-report.mjs. Express сам выбирает Brotli/gzip/обычный файл по Accept-Encoding; nginx и дополнительные зависимости не нужны. Сжатие выполняется при сборке, а не при каждом запросе. Хэшированные скрипты, CSS, шрифты и WebP кэшируются на год; HTML требует перепроверки. Отчёт сборки проверяет, что Phaser не попал в начальный граф загрузки и начальный JS не превысил бюджет 64 KiB.

Исправлены ответы от устаревшего подключения, восстановление броска при переподключении, проверка сохранённого профиля и обрезание карты минимальным зумом на небольших экранах. Неподвижные персонажи больше не пересчитывают позиции и сортировку каждый кадр, неизменившийся список аватаров не пересоздаёт DOM. Перед выпуском проверены вход, повторный вход, восстановление позиции после перезагрузки, бросок и очередь в двух вкладках, пауза, финальные карточки и отсутствие ошибок консоли в этих сценариях. npm test дополнительно проверяет согласование сжатия, MIME, кэширование, безопасные пути ресурсов, сохранённую сессию и вписывание карты на разных разрешениях.
### Приветствие, границы камеры и фавиконка

После первого успешного входа участника в комнату поверх карты показывается приветственная карточка «Добро пожаловать в Загробный мир!» с кнопкой «Продолжить». При повторном подключении того же игрока она не повторяется; признак показа хранится в sessionStorage и памяти вкладки. До закрытия приветствия игровые действия заблокированы. Текст — src/config/welcome.ts.

Минимальный зум рассчитывается так, чтобы фон покрывал всю область камеры без чёрных полос. Панорамирование тоже ограничено границами фона; на экранах с другим соотношением сторон фон может обрезаться по краям, но за него нельзя выехать или отдалиться.

Фавиконка — оранжевая тыква с мордочкой на тёмном фоне: public/favicon.svg, favicon.ico и apple-touch-icon.png. Исходный SVG редактируется вручную; scripts/create-favicon.mjs пересобирает PNG/ICO из SVG через установленный sharp. Иконка подключена на страницах игры и админки.
### Музыка и звуки

Фоновый плейлист использует все 8 добавленных треков Spooky от AlkaKrab. Один HTML audio-элемент последовательно проигрывает треки и возвращается к первому; музыка загружается по одному файлу, без декодирования всего пака в память. Звук запускается после взаимодействия пользователя с игрой. При скрытии вкладки музыка приостанавливается.

Кнопки используют CozyChimeUI, выбор персонажа — Retro8-bitUI; монеты и сладости — coin/sparkle; призрак, зелье, проклятие и портал — Magic; метла — arrow_flyby. Кубик использует короткий деревянный click_wood при броске и reel_stop при остановке, открытие карточки — card_deal, свой ход — notification, победа — levelup, проигрыш — тихий deep_impact. В добавленных паках нет отдельных шагов, поэтому движение сопровождается тихим tile_swap с небольшой вариацией тона. Неиспользуемые боевые и лазерные эффекты не загружаются.

Короткие эффекты декодируются только при первом использовании и кэшируются; одновременно звучит не более 6. Подбор, кубик и движение привязаны к общему серверному состоянию и времени движения. Повторные снимки и переподключение не запускают уже прошедшие эффекты. Пауза останавливает эффекты и приглушает музыку.

Вверху справа находятся отключение звука и настройки отдельной громкости музыки/эффектов. Выбор сохраняется в localStorage. Конфигурация — src/config/audio.ts, воспроизведение — src/audio/AudioManager.ts, игровые сигналы — src/audio/GameAudio.ts и cues.ts. Сведения об авторах — public/licenses/audio-credits.txt. Начальный JS после добавления аудио составляет около 22 КБ; аудиофайлы не входят в его содержимое и не загружаются целиком при открытии страницы.
Игровой canvas использует RESIZE: при изменении размера окна он занимает весь контейнер. Камера пересчитывает минимальный зум по границам фона с сохранением относительного увеличения; margin-collapse canvas не сдвигает DOM-интерфейс.


### Проверка перед продом — 30 октября 2026

Кубик использует тихий сухой щелчок; chip_stack и lever_pull исключены из сборки. Для разных сладостей, старта, паузы, продолжения, входа/выхода участников, движения по результату события и выбора цели используются отдельные звуки. Эффекты, загрузка которых задержалась больше 350 мс, не проигрываются задним числом; декодированный файл остаётся в кэше для следующих действий. Скрытые за камерой предметы не пересчитывают парение каждый кадр.

Socket.IO проверяет Origin при первом подключении: в проде браузер должен открывать игру с того же хоста и порта, что сервер. Другой localhost-порт разрешён только в явно включённом локальном dev-режиме. Запросы без Origin допустимы для небраузерных клиентов; проверки приглашения, личности и очереди остаются обязательными. Добавлены nosniff и Referrer-Policy: same-origin, чтобы ссылка приглашения не уходила в Referer сторонних сайтов.

Проверки: npm test — 89 тестов, включая реальные подключения 10 участников, очередь и переподключение, админку, паузу, цепочки эффектов, финиш и запрет сторонних Origin. npm audit --omit=dev — 0 известных уязвимостей на момент проверки. Это состояние реестра на дату проверки, не постоянная гарантия.

Прод запускается одной командой npm start: подготовка ассетов, проверка типов, сборка клиента и сервера, предсжатие ресурсов и запуск Express. Для прод-запуска не используйте start:dev. Состояние хранится в памяти; перезапуск очищает партии.
